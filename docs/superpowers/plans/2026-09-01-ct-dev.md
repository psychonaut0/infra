# ct-dev Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up `ct-dev`, an always-on LXC that holds the work monorepo and keeps Claude Code sessions alive across disconnects, reachable over Tailscale from any device.

**Architecture:** An unprivileged Debian 13 LXC (VMID 116, `192.168.3.19`) on proxmoxmain, running as `psy` UID 1000 at a path byte-identical to the workstation. Provisioning is written as two idempotent scripts committed to `stacks/ct-dev/` — one for the hypervisor, one for inside the container — so recovery is *recreate and re-run*, never *restore*. Each task appends its section to those scripts, runs it, and verifies.

**Tech Stack:** Proxmox LXC, Debian 13 (Trixie), Go 1.26, Node 26, Bun 1.3.13, Docker + compose, AWS CLI v2, Tailscale, tmux, Claude Code.

**Spec:** `docs/superpowers/specs/2026-08-31-ct-dev-design.md`

## Global Constraints

- **This infra repo is public.** Never commit the work repo's real name, the SSO start URL, profile names, or any employer specifics. Use `<WORK_REPO>`; real values live in `CLAUDE.local.md`.
- **Path is load-bearing:** `/home/psy/Documents/work/travelware/<WORK_REPO>`, user `psy` **UID 1000**. Changing either breaks the git `includeIf` identity and the Claude session-directory encoding.
- **Version floors (enforced by the monorepo's `preinstall`):** Go 1.26, Node 26, Bun 1.3.13.
- **No backups of ct-dev.** Do **not** add ct-dev to `CT_IPS` in `stacks/ct-backup/scripts/pre-backup.sh`.
- **No notification service.** Batch results are pulled (`dev-task list` / `log` / MOTD). Telegram was explicitly rejected.
- **No long-lived AWS keys**, ever. SSO only.
- **Never pin a repo-local `AWS_CONFIG_FILE`** — it breaks the `travelogue` CLI.
- Scripts are **idempotent**: safe to re-run in full at any point.
- Follow the ct-backup precedent: **committed is not deployed.** Every task runs its script against the real host.
- **Phase 3 (browser fallback via `ttyd` + dedicated Cloudflare Tunnel) is NOT in this plan.** It gets its own plan and its own security review.

### Task 1: Host prerequisites on proxmoxmain

**Files:**
- Create: `stacks/ct-dev/provision-host.sh`

**Interfaces:**
- Consumes: nothing.
- Produces: `vm.max_map_count=262144` persistent on proxmoxmain; the script skeleton later tasks append to.

- [ ] **Step 1: Verify the current effective value (the "before" baseline)**

```bash
ssh proxmoxmain "sysctl -n vm.max_map_count"
```
Expected: `262144` (from PVE's `/usr/lib/sysctl.d/10-pve-ct-inotify-limits.conf`) — i.e. already meeting the floor. If lower, systemd 257's default would be `1048576` instead.

- [ ] **Step 2: Write the script with floor-only logic**

```bash
mkdir -p stacks/ct-dev
cat > stacks/ct-dev/provision-host.sh <<'EOF'
#!/bin/bash
# Provisions ct-dev (VMID 116) on proxmoxmain. Idempotent: safe to re-run.
# Usage: run ON proxmoxmain as root.
set -euo pipefail

VMID=116
HOSTNAME=ct-dev
IP=192.168.3.19
GW=192.168.3.1
DNS=192.168.3.5

log() { echo "[ct-dev] $*" >&2; }

# --- 1. Host sysctl -------------------------------------------------------
# The work monorepo's compose stack runs OpenSearch, which requires
# vm.max_map_count >= 262144. This sysctl is NOT namespaced, so it cannot be
# set from inside the container -- it must live on the hypervisor.
# Floor-only: only write /etc/sysctl.d/99-ct-dev.conf if the effective value
# is below the floor. Never lower the system default.
current=$(sysctl -n vm.max_map_count)
if [[ $current -lt 262144 ]]; then
  log "vm.max_map_count is $current, below floor 262144; setting to 262144"
  install -d -m 755 /etc/sysctl.d
  echo 'vm.max_map_count=262144' > /etc/sysctl.d/99-ct-dev.conf
  sysctl -p /etc/sysctl.d/99-ct-dev.conf >/dev/null
else
  log "vm.max_map_count is $current, meets floor 262144 (system or distro default)"
  rm -f /etc/sysctl.d/99-ct-dev.conf
fi
# Assert the floor is met
final=$(sysctl -n vm.max_map_count)
if [[ $final -lt 262144 ]]; then
  log "FAIL: effective vm.max_map_count=$final is below floor 262144"
  exit 1
fi
EOF
chmod +x stacks/ct-dev/provision-host.sh
```

- [ ] **Step 3: Copy to the host and run it**

```bash
scp stacks/ct-dev/provision-host.sh proxmoxmain:/root/provision-host.sh
ssh proxmoxmain "bash /root/provision-host.sh"
```

- [ ] **Step 4: Verify it does not lower the default, and is idempotent**

```bash
ssh proxmoxmain "sysctl -n vm.max_map_count; ls /etc/sysctl.d/99-ct-dev.conf 2>&1; grep -rs max_map_count /etc/sysctl.d/ /usr/lib/sysctl.d/"
```
Expected: `262144` (unchanged), no such file in /etc, and only PVE/systemd entries in /usr/lib. Re-run Step 3 — it must succeed again with identical output (idempotence).

- [ ] **Step 5: Commit**

```bash
git add stacks/ct-dev/provision-host.sh
git commit -m "feat(ct-dev): host sysctl prerequisite for the search service"
```

- [ ] **Step 2: Append CT creation to the script**

Set `TEMPLATE` to the exact filename from Step 1.

```bash
cat >> stacks/ct-dev/provision-host.sh <<'EOF'

# --- 2. Container ---------------------------------------------------------
TEMPLATE="${TEMPLATE:-local:vztmpl/debian-13-standard_13.0-1_amd64.tar.zst}"

if ! pct status "$VMID" >/dev/null 2>&1; then
  log "creating CT $VMID"
  pct create "$VMID" "$TEMPLATE" \
    --hostname "$HOSTNAME" \
    --cores 6 --memory 12288 --swap 4096 \
    --rootfs local-lvm:120 \
    --net0 "name=eth0,bridge=vmbr0,firewall=1,gw=${GW},ip=${IP}/24,type=veth" \
    --nameserver "$DNS" \
    --ostype debian \
    --unprivileged 1 \
    --features nesting=1,keyctl=1 \
    --onboot 1
else
  log "CT $VMID already exists, skipping create"
fi

# --- 3. CT config: Docker-in-LXC + Tailscale TUN --------------------------
# AppArmor unconfined and rw /proc/sys match the rest of the fleet's
# Docker-in-LXC pattern. The /dev/net/tun passthrough is NEW for this fleet --
# Tailscale cannot create its interface in an unprivileged LXC without it.
CONF="/etc/pve/lxc/${VMID}.conf"
add_conf() {
  grep -qxF "$1" "$CONF" || { log "conf += $1"; echo "$1" >> "$CONF"; }
}
add_conf 'lxc.apparmor.profile: unconfined'
add_conf 'lxc.mount.entry: /proc/sys proc/sys none bind,rw 0 0'
add_conf 'lxc.cgroup2.devices.allow: c 10:200 rwm'
add_conf 'lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file'

pct status "$VMID" | grep -q running || { log "starting CT"; pct start "$VMID"; }
EOF
```

```bash

ssh proxmoxmain "pct exec 116 -- ping -c2 192.168.3.5"
```

Expected: `status: running`; config shows `unprivileged: 1`, `features: nesting=1,keyctl=1`, all four `lxc.*` lines; DNS ping succeeds.

- [ ] **Step 1: Confirm the user does not exist yet**

```bash

```
Expected: `id: 'psy': no such user`

- [ ] **Step 2: Write the CT provisioning script**

```bash
cat > stacks/ct-dev/provision-ct.sh <<'EOF'
#!/bin/bash
# Provisions the inside of ct-dev. Idempotent: safe to re-run.
# Usage: run INSIDE ct-dev as root.
set -euo pipefail

USER_NAME=psy
USER_UID=1000
REPO_PARENT="/home/${USER_NAME}/Documents/work/travelware"

log() { echo "[ct-dev] $*" >&2; }
as_user() { runuser -u "$USER_NAME" -- "$@"; }

export DEBIAN_FRONTEND=noninteractive

# --- 1. Base packages -----------------------------------------------------
apt-get update -qq
apt-get install -y -qq \
  ca-certificates curl wget gnupg git git-lfs jq ripgrep unzip zip \
  build-essential pkg-config sudo tmux locales less python3 python3-venv pipx

# --- 2. Locale + timezone -------------------------------------------------
sed -i 's/^# *en_US.UTF-8/en_US.UTF-8/' /etc/locale.gen
locale-gen >/dev/null
timedatectl set-timezone Europe/Rome 2>/dev/null || ln -sf /usr/share/zoneinfo/Europe/Rome /etc/localtime

# --- 3. User --------------------------------------------------------------
# UID 1000 and the exact home path are load-bearing: the git includeIf work
# identity and Claude Code's project-directory encoding both key off the path.
if ! id "$USER_NAME" >/dev/null 2>&1; then
  log "creating user $USER_NAME"
  useradd -m -u "$USER_UID" -s /bin/bash "$USER_NAME"
fi
install -d -m 755 -o "$USER_NAME" -g "$USER_NAME" "$REPO_PARENT"

echo "$USER_NAME ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/90-"$USER_NAME"
chmod 440 /etc/sudoers.d/90-"$USER_NAME"

# --- 4. SSH ---------------------------------------------------------------
install -d -m 700 -o "$USER_NAME" -g "$USER_NAME" "/home/$USER_NAME/.ssh"
if [ -f /root/ct-dev-authorized_keys ]; then
  install -m 600 -o "$USER_NAME" -g "$USER_NAME" \
    /root/ct-dev-authorized_keys "/home/$USER_NAME/.ssh/authorized_keys"
fi
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
EOF
chmod +x stacks/ct-dev/provision-ct.sh
```

- [ ] **Step 2: Append the toolchain install**

Debian 13 ships none of these at the required versions, so all three come from upstream tarballs pinned to exact versions.

```bash
cat >> stacks/ct-dev/provision-ct.sh <<'EOF'

# --- 6. Language toolchain ------------------------------------------------
# Versions are pinned to satisfy the monorepo's preinstall gates
# (scripts/check-node.sh and scripts/check-go.sh). Debian 13 packages are too
# old for all three, so each comes from an upstream tarball.
GO_VERSION=1.26.0
NODE_VERSION=26.7.0
BUN_VERSION=1.3.13

ARCH=$(dpkg --print-architecture)   # amd64
case "$ARCH" in
  amd64) GO_ARCH=amd64; NODE_ARCH=x64; BUN_ARCH=x64 ;;
  *) echo "unsupported arch $ARCH" >&2; exit 1 ;;
esac

if [ "$(/usr/local/go/bin/go version 2>/dev/null | awk '{print $3}')" != "go${GO_VERSION}" ]; then
  log "installing go ${GO_VERSION}"
  curl -fsSL "https://go.dev/dl/go${GO_VERSION}.linux-${GO_ARCH}.tar.gz" -o /tmp/go.tgz
  rm -rf /usr/local/go && tar -C /usr/local -xzf /tmp/go.tgz && rm /tmp/go.tgz
fi

if [ "$(/usr/local/node/bin/node --version 2>/dev/null)" != "v${NODE_VERSION}" ]; then
  log "installing node ${NODE_VERSION}"
  curl -fsSL "https://nodejs.org/dist/v${NODE_VERSION}/node-v${NODE_VERSION}-linux-${NODE_ARCH}.tar.xz" -o /tmp/node.txz
  rm -rf /usr/local/node && mkdir -p /usr/local/node
  tar -C /usr/local/node --strip-components=1 -xJf /tmp/node.txz && rm /tmp/node.txz
fi

if [ "$(/usr/local/bun/bin/bun --version 2>/dev/null)" != "$BUN_VERSION" ]; then
  log "installing bun ${BUN_VERSION}"
  curl -fsSL "https://github.com/oven-sh/bun/releases/download/bun-v${BUN_VERSION}/bun-linux-${BUN_ARCH}.zip" -o /tmp/bun.zip
  rm -rf /usr/local/bun && mkdir -p /usr/local/bun/bin
  unzip -qo /tmp/bun.zip -d /tmp/bunx
  install -m 755 "/tmp/bun-linux-${BUN_ARCH}/bun" /usr/local/bun/bin/bun 2>/dev/null \
    || install -m 755 "/tmp/bunx/bun-linux-${BUN_ARCH}/bun" /usr/local/bun/bin/bun
  rm -rf /tmp/bun.zip /tmp/bunx "/tmp/bun-linux-${BUN_ARCH}"
fi

cat > /etc/profile.d/ct-dev-path.sh <<'PATHEOF'
export PATH="/usr/local/go/bin:/usr/local/node/bin:/usr/local/bun/bin:$HOME/.local/bin:$PATH"
export GOPATH="$HOME/go"
PATHEOF
chmod 644 /etc/profile.d/ct-dev-path.sh
EOF
```

### Task 7: AWS tooling — four binaries

**Files:**
- Modify: `stacks/ct-dev/provision-ct.sh` (append)

**Interfaces:**
- Consumes: script from Task 6.
- Produces: `aws`, `session-manager-plugin`, `pgcli`, and `travelogue` on PATH.

**Context the implementer needs:** the project's `travelogue` CLI is a **separate Go binary distributed via Bitbucket downloads** — it is not in the monorepo and `bun install` does not provide it. It self-updates with `travelogue update` and refuses to run if `aws` is not on PATH. Because the download URL requires Bitbucket credentials, the reliable path is to **copy the existing binary from BLVCKFlow** and then let it self-update. (An older memory names BLVCKSmall as the reference machine — BLVCKSmall is retired; use BLVCKFlow.)

- [ ] **Step 1: Confirm the tooling is absent**

```bash
ssh ct-dev "command -v aws session-manager-plugin pgcli travelogue || echo 'aws tooling absent'"
```
Expected: `aws tooling absent`

- [ ] **Step 2: Append the installs**

```bash
cat >> stacks/ct-dev/provision-ct.sh <<'EOF'

# --- 8. AWS tooling -------------------------------------------------------
# Four separate binaries. Unlike BLVCKFlow (where sudo needs a password and
# these live userland under ~/.local), ct-dev has root, so all install
# system-wide.
if ! command -v aws >/dev/null 2>&1; then
  log "installing aws cli v2"
  curl -fsSL "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o /tmp/awscliv2.zip
  unzip -qo /tmp/awscliv2.zip -d /tmp && /tmp/aws/install --update
  rm -rf /tmp/awscliv2.zip /tmp/aws
fi

if ! command -v session-manager-plugin >/dev/null 2>&1; then
  log "installing session-manager-plugin"
  curl -fsSL "https://s3.amazonaws.com/session-manager-downloads/plugin/latest/ubuntu_64bit/session-manager-plugin.deb" \
    -o /tmp/smp.deb
  apt-get install -y -qq /tmp/smp.deb && rm /tmp/smp.deb
fi

if ! as_user bash -lc 'command -v pgcli' >/dev/null 2>&1; then
  log "installing pgcli"
  as_user bash -lc 'pipx install pgcli'
fi

# travelogue CLI: copied in by the operator (see README), then self-updating.
if [ -f /root/travelogue ] && [ ! -x /usr/local/bin/travelogue ]; then
  log "installing travelogue cli"
  install -m 755 /root/travelogue /usr/local/bin/travelogue
```

### Task 11: `dev-task` — batch work with nothing attached

**Files:**
- Create: `stacks/ct-dev/bin/dev-task`
- Modify: `stacks/ct-dev/provision-ct.sh` (append)

**Interfaces:**
- Consumes: `claude` on PATH (Task 9).
- Produces: `dev-task run|list|log` in `/usr/local/bin`, plus an MOTD summary of finished tasks.

- [ ] **Step 1: Write the wrapper**

```bash
mkdir -p stacks/ct-dev/bin
cat > stacks/ct-dev/bin/dev-task <<'EOF'
#!/bin/bash
# dev-task — run Claude Code headless under a transient systemd user unit, so
# work continues with no terminal attached. Results are PULLED, not pushed:
# there is deliberately no notification service.
set -euo pipefail

STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/dev-task"
mkdir -p "$STATE_DIR"

usage() {
  cat >&2 <<USAGE
usage:
  dev-task run <name> "<prompt>"   start a headless task
  dev-task list                    show task states
  dev-task log <name>              tail a task's output
USAGE
  exit 2
}

cmd_run() {
  local name="${1:?task name required}"; shift
  local prompt="${*:?prompt required}"
  local log="$STATE_DIR/${name}.log"
  : > "$log"
  systemd-run --user --unit="dev-task-${name}" \
    --working-directory="$PWD" \
    --setenv=HOME="$HOME" \
    --property=StandardOutput="append:${log}" \
    --property=StandardError="append:${log}" \
    claude -p "$prompt"
  echo "started dev-task-${name} (log: ${log})"
}

cmd_list() {
  systemctl --user list-units 'dev-task-*' --all --no-legend --no-pager \
    | awk '{printf "%-32s %s %s\n", $1, $3, $4}'
}

cmd_log() {
  local name="${1:?task name required}"
  tail -f "$STATE_DIR/${name}.log"
}

case "${1:-}" in
  run)  shift; cmd_run "$@" ;;
  list) cmd_list ;;
  log)  shift; cmd_log "$@" ;;
  *)    usage ;;
esac
EOF
chmod +x stacks/ct-dev/bin/dev-task
```

- [ ] **Step 2: Append install + MOTD, including lingering**

`systemd-run --user` units die when the last session closes unless lingering is enabled — that is exactly the failure this feature exists to prevent.

```bash
cat >> stacks/ct-dev/provision-ct.sh <<'EOF'

# --- 12. dev-task ---------------------------------------------------------
if [ -f /root/ct-dev-files/dev-task ]; then
  install -m 755 /root/ct-dev-files/dev-task /usr/local/bin/dev-task
fi

# Without lingering, user units are killed when the last session ends -- which
# would defeat the entire point of detached batch tasks.
loginctl enable-linger "$USER_NAME"

# Login summary. NOT /etc/update-motd.d -- those run as root under pam_motd,
# so $HOME would be /root and `systemctl --user` would query the wrong user.
# This must run as psy, so it goes in the user's bashrc.
BASHRC="/home/$USER_NAME/.bashrc"
if ! grep -q 'dev-task summary' "$BASHRC" 2>/dev/null; then
  cat >> "$BASHRC" <<'RCEOF'

# dev-task summary on interactive login
if [ -n "$PS1" ]; then
  _dt=$(systemctl --user list-units 'dev-task-*' --all --no-legend --no-pager 2>/dev/null)
  if [ -n "$_dt" ]; then
    printf '\ndev-task:\n'
    printf '%s\n' "$_dt" | awk '{printf "  %-28s %s\n", $1, $4}'
    printf '\n'
  fi
  unset _dt
fi
RCEOF
  chown "$USER_NAME:$USER_NAME" "$BASHRC"
fi
EOF
```
